3. 第一次 FBX 导出后的异常
============================================================

第一次 FBX 导出后，Unity 中 FBX Preview：

但将同一个 Animation Clip 放入 GLB 的 Animator：

Controller = GLB_Test_Controller
Avatar = None

进入 Play 后：
- 小臂确实受到动画驱动；
- 但 GLB 部分结构突然冲到 Camera 前；
- Game View 出现大块黑灰几何体，视觉上最初像 Camera 突然换了视角。

============================================================
4. Camera 排查
============================================================

最初怀疑：
- FBX 自带 Camera 抢占 Game View；
- Main Camera 在 Play 时被脚本移动；
- Main Camera 父节点发生移动。

逐项验证：

1. 删除 Hierarchy 中 FBX Scene Instance；
2. FBX 内部 Camera / Light 仅作为 Project Asset 子对象存在，不参与 Scene；
3. Main Camera 为 Hierarchy 顶层对象，无父节点；
4. Play 前后 Main Camera Transform 数值不变；
5. 禁用 Main Camera 后，场景无其他 Camera 渲染；
6. 禁用 jesss 的 Animator 后，冲到 Camera 前的异常立即消失。

结论：
Camera 本身没有移动。
异常来自 Animator 播放 FBX Clip 后 GLB 的 Transform / 骨骼状态变化。

============================================================
5. Unity Animation Clip 的异常信号
============================================================

第一次 FBX 的 Animation Clip Inspector 显示约：

Curves Pos:        171
Quaternion:        171
Scale:             171

但 Blender Action Editor 已确认：
实际只给 J_Bip_L_LowerArm 制作了关键帧。

这说明：
全骨架 Transform 曲线不是动画制作阶段产生，
而是在 FBX 导出 / 烘焙阶段写入。

============================================================

============================================================
7. 根因定位：Blender Key All Bones
============================================================

检查 Blender FBX Export → Animation：

Key All Bones = ON
NLA Strips    = ON
All Actions   = ON

其中 Key All Bones 会在导出动画时给骨架中的骨骼写入关键数据，
即使 Blender Action 中并未手动给这些骨骼制作动画。

这与 Unity 中出现 171 组 Pos / Rotation / Scale 曲线的现象对应。

同时第一次导出 Object Types 包含：
Empty / Camera / Lamp / Armature / Mesh / Other

因此 FBX 中还额外携带了 Blender Camera 和 Light。

12. 本轮最终结论
============================================================

已验证：

→ GLB 角色本体

Blender Action
→ clean FBX Animation
→ Unity Animator
→ 同骨架 GLB

成立。

本轮最关键的坑：

FBX 动画导出时不要默认开启 Key All Bones，
否则未参与动画的整套骨架 Transform 也可能被写入 Clip。

当该 Clip 用于另一个独立导出的同骨架模型时，
这些无关 Transform 曲线可能覆盖模型自己的基础姿态 / Transform，
表现为模型爆开、位移、冲向 Camera 等异常。

============================================================
13. 以后遇到类似问题的 Checklist
============================================================

当“FBX Preview 正常，但同一个 Clip 套到 GLB 后模型炸掉”时：

1. 先确认 Camera 是否真的移动；
2. 禁用 Animator，确认异常是否由动画触发；
3. 检查 Blender Action Editor：到底哪些骨骼真的有 Key；
4. 检查 Unity Clip 的 Pos / Quaternion / Scale 曲线数量；
5. 检查 Blender FBX Export 的 Key All Bones；
6. 单动作测试关闭 NLA Strips / All Actions；
7. 不把 Camera / Light 带入动画 FBX；
8. 重新导入后先看曲线数量，再挂到正式 GLB；
9. 最后再处理 Local Axis / Rest Pose 等动作方向问题。

本轮最关键的一句：

“FBX 自己播放正常”不等于“这个 Clip 是干净、可复用的独立动作资产”。
