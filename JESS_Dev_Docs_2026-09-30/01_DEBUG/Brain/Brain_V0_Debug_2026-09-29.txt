================================================== 一、阶段目标
==================================================

本阶段目标不是训练完整的 JESS
人格，也不是让模型直接控制身体，而是先跑通最小 Brain 链路：

Unity → JessBrain → LLMClient → 阿里云百炼 / Qwen → 返回结果到 Unity

在普通文本回复成功后，再升级为：

用户文字 → Brain → JSON ├─ reply ├─ expression └─ action → Unity 解析

这样后续可以分别把 reply 交给 TTS，把 expression/action 交给 JESS
的表情与身体执行层。

================================================== 二、当前脚本结构
==================================================

Assets/scripts/brain/ ├─ LLMClient.cs └─ JessBrain.cs

LLMClient.cs： 负责 API 通信，不负责 JESS 的角色人格。

JessBrain.cs： 负责 JESS 的 Prompt、输入内容以及解析 Brain 输出。

设计原则： Character Brain 与具体 LLM Provider 尽量解耦。
目前使用阿里云百炼 / Qwen，后续如更换模型，优先只修改 LLMClient / API
配置，而不破坏上层 Brain 接口。

==================================================
九、已知但暂不处理的问题：JESS 人格
==================================================

当前模型输出：

“抱抱，快去躺平，我给你放点轻音乐。”

技术上完全正确，但角色人格明显不符合目前设想中的 JESS。

原因： 当前 system prompt 只提供了极弱的人格描述，例如：
“你叫JESS，是一个自然、有个性的数字人。”

因此 Qwen 会倾向生成通用、友善、陪伴型 AI 的表达方式。

这不是 Brain 接口故障，而是 Character Prompt / Character Brain
尚未设计。

后续人格层需要单独处理，例如： - JESS 的语言风格 - mean / 嘴硬程度 -
情绪表达方式 - 关心用户时是否直接表达 - 表面语言与真实情绪之间的反差 -
什么情况下会出现罕见的温柔 - 长期关系与记忆如何改变表达

重要观察： 如果 JESS 平时较
mean、克制、嘴硬，那么偶尔出现真正温柔的表达可能具有更强的关系意义。
这种“反差”不应成为默认输出，否则会失去角色张力。

但以上属于后续 Character Brain / Character Spec 工作，不影响当前 Brain
V0 工程接口。
