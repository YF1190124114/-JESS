JESS macOS 麦克风 / Build Runbook
来源：macOS 麦克风 Bug 排查与开发复用日志
用途：以后需要真实语音测试或重新 Build 时直接查看。

==================================================
1. 当前事实
==================================================

Unity Editor：
- Microphone API 表面可启动
- PCM 实测仍为 0
- 当前不能用于真实 ASR 录音测试

macOS Standalone Build：
- 已真实获得麦克风权限
- 已读到非零 PCM
- 已完成 Alibaba NLS ASR
- 已返回真实识别文字

因此真实麦克风 / ASR 验证应使用 Standalone Build。

==================================================
2. 已验证的完整链
==================================================

人的声音
→ MacBook Pro 麦克风
→ macOS 麦克风权限
→ Unity Microphone
→ AudioClip
→ PCM16
→ Alibaba Cloud NLS
→ 识别文字

==================================================
3. 关键 Build 问题
==================================================

曾发现：
Unity Player Settings 虽填写 Microphone Usage Description，
但最终 .app 的 Contents/Info.plist 中没有：
NSMicrophoneUsageDescription

手工补入后，并完成：
- 清理扩展属性
- 重新 codesign
- tccutil reset Microphone <Bundle ID>
- 重新启动 App

macOS 才正式弹出麦克风授权，并成功录音。

==================================================
4. 当前开发方式
==================================================

日常开发：
- Brain：用测试字符串
- Body：直接测试 expression / action
- 未来 TTS：用固定字符串或 Brain.reply
- 不需要为了每次开发都重新 Build

只有验证：
真实麦克风 / macOS 权限 / 最终全链路
时才 Build。

==================================================
5. 下一项工程化任务
==================================================

目前手工修改 Info.plist 的流程不能作为正式交付方案。

后续应增加 macOS Post-build Script：

Unity Build
→ 自动检查 / 写入 NSMicrophoneUsageDescription
→ 生成可正常请求麦克风权限的 JESS.app

Unity Editor 麦克风问题值得以后研究，但当前不是阻塞项。

==================================================
6. ASR Token
==================================================

NLS 临时 Token 会过期。
若此前正常、之后请求突然失败，应检查 Token 是否已过期。

正式版本不应依赖每天手工替换临时 Token；
后续需要自动获取 / 刷新 Token。
