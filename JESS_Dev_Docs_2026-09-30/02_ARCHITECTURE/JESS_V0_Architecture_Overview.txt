==================================================
2. 当前运行时信息流
==================================================

Brain 当前产生：

BrainResult
├─ reply
├─ expression
└─ action

输出分发：

reply
→ JessSpeechController
→ IJessSpeechDriver 所定义的 Speak 契约
→ AliyunTtsDriver
→ AudioSource

expression
→ JessExpressionController
→ IJessExpressionDriver
→ 当前选中的 JessBlendShapeExpressionDriver
→ Blender / GLB Mesh BlendShape

action
→ JessActionController
→ IJessActionDriver
→ JessAnimatorActionDriver
→ Animator

重要实现细节：
- AliyunTtsDriver 已实现 IJessSpeechDriver；
- 当前 JessSpeechController 的序列化字段类型仍是具体的 AliyunTtsDriver，
  因此“Controller → Interface → Driver”是当前逻辑契约，
  但 Inspector 绑定仍是 V0 的具体 Driver 绑定；
- JessBrain 当前在 Start 中使用固定 testInput 调用 LLM；
- MicrophoneRecorder 得到 ASR result 后目前只记录日志，
  尚未把 userText 送入 JessBrain。

因此 Perception → Brain → Output 是已经建立的模块边界，
但“真实 ASR 文本自动进入 Brain”的运行闭环尚未完成。

→ JessSpeechController
→ IJessSpeechDriver 契约

三项 targetWeight 当前均为 1。

fake_smile 曾通过临时强制 expression 的方式完成 Play Mode 验证。
该临时代码未保留在提交中，当前脚本也不存在
SetExpression("fake_smile") 或其他强制 fake_smile 逻辑。

同时需要注意：
JessBrain 当前 expression 白名单仍为：

因此 fake_smile 已有模型映射并做过人工验证，
但当前正常 Brain 输出不会自动选择 fake_smile。

==================================================
6. 核心设计边界
==================================================

Brain 只输出 JESS 语义，不应知道：
- Bone name
- BlendShape / Shape Key name
- VRM ExpressionKey
- Animator 的具体模型细节

Controller 负责：
“JESS 想做什么”。

Driver / Adapter 负责：
“当前模型或服务怎么做到”。

Scene / Model / AudioSource / Animator 负责实际执行。

未来更换 TTS Provider、角色模型或动画实现时，
优先替换 Driver、映射和资产引用，避免重写 Brain。
